Prompt engineering for QA engineers

Use AI for QA work without generic answers. This lesson follows the R-C-T-F frame: Role, Context, Task, and Format.

Step 1: Use R-C-T-F

  • Role: Tell AI who to act as: QA lead, SDET, API tester, automation engineer, or reviewer.
  • Context: Paste feature details, stack, risks, acceptance criteria, logs, API contract, or existing code.
  • Task: Ask for one clear output: strategy, plan, cases, test data, code, bug report, or review.
  • Format: Force a usable result: table, checklist, Jira bug, test file, or review report.

Step 2: Design QA Work

  • Test strategy: Ask for scope, test levels, tooling, environments, entry/exit criteria, and risk matrix.
  • Test plan: Convert stories and acceptance criteria into milestones, owners, test data, and deliverables.
  • Test cases: Generate happy, negative, boundary, edge, permission, validation, and regression scenarios.
  • Test data: Ask for valid, invalid, boundary, duplicate, expired, missing, and role-based datasets.

Step 3: Build & Review

  • API tests: Paste endpoint details and ask for status, schema, auth, and contract checks.
  • Automation: Convert manual cases into Selenium or Playwright tests with Page Object Model.
  • Bug reports: Turn raw notes, screenshots, logs, and repro steps into clean triage-ready reports.
  • Refactor: Find flaky waits, brittle locators, missing assertions, duplication, and cleanup ideas.

Step 4: Improve Output

  • Add team examples so AI follows your style.
  • Add constraints like no hard waits, use test IDs, max 12 cases, or avoid XPath.
  • Ask follow-ups: add negative cases, rank by risk, find gaps, simplify, or convert to code.
  • Never ship unread. Review, run, and own every AI-generated test or report.
